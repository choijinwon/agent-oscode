# 코딩 에이전트 비교와 OSCODE 적용


## 2026-09-20 비교: 프론트엔드 정확도와 입력 범위

OpenCode, Pi, Claude Code와 Codex·Aider·Cursor·Gemini CLI·Cline의 공식 문서·README를 확인했습니다. 아래는 OSCODE의 코드 탐색, 컨텍스트 관리, 확장, 작업 연속성에 필요한 기능 비교이며 제품 전체의 기능 수·인기·품질 순위는 아닙니다. 제3자 코드를 복사하거나 해당 도구를 의존성으로 추가한 작업이 아닙니다.

| 도구 | 확인한 설계·기능 | OSCODE 현황과 적용 판단 |
| --- | --- | --- |
| [OpenCode: LSP](https://opencode.ai/docs/lsp/) | 언어 서버 진단을 에이전트에 제공. 현재 문서는 기본 비활성화와 메모리·버전·지연의 비용도 설명 | 기존 프로젝트 검사 유지. 이번에는 설치·서버 실행 없는 프론트엔드 정적 영향 분석 확장. 전체 LSP는 후속 검토 |

| [Aider: repository map](https://aider.chat/docs/repomap.html) | 심볼과 의존 관계를 그래프로 평가해 토큰 예산 내 관련 정보를 선택 | 기존 `/map` 유지. `/impact`에 역참조 경로·테스트/화면 우선 표시·출력 예산 추가. Aider 순위 알고리즘과 동일하지 않음 |
| [Cursor: rules](https://cursor.com/docs/rules) | 프로젝트에서 재사용하는 범위별 지침 | 팀 공통 지침은 AGENTS.md, 파일별 지침은 `.oscode/rules`, 직접 선택하는 작업은 `/skills`로 구분 |
| [Gemini CLI: GEMINI.md](https://geminicli.com/docs/cli/gemini-md/) | 프로젝트·디렉터리 문맥과 로드한 메모리 확인 | `/rules explain`·`/rules last`로 왜 포함됐는지와 실제 요청 시점을 확인 |
| [Cline: task management](https://docs.cline.bot/core-workflows/task-management) | 작업 단위 이력과 재개, 체크포인트 | 기존 세션 재개·파일 체크포인트·인계 유지. 별도 작업 이력 시스템을 중복 추가하지 않음 |

현재 Pi의 예전 `badlogic/pi-mono` coding-agent 경로는 위 저장소로 연결됩니다. OpenCode의 LSP 문서와 이전 권한 비교의 v2 문서는 별도 문서이므로 설정 스키마를 혼용하지 않았습니다.

### 구현한 기능

1. **프론트엔드 변경 영향 분석 확장**: JS/TS 외에 Vue·Svelte script, 따옴표 스타일 import, Angular의 외부 템플릿·스타일을 추적합니다. 줄 번호가 있는 역참조 경로, 테스트·화면 후보, 해시 기반 파싱 재사용, 생략 수와 분석 한계를 제공합니다. API 없이 `/impact 파일경로`로 사용할 수 있습니다.
2. **경로별 프로젝트 규칙**: 첨부 파일과 이번 턴에서 읽은 파일의 규칙만 최대 추정 2,000 토큰으로 로드합니다. 편집·생성 전에 새 규칙이 발견되면 모델이 읽을 수 있도록 작업을 다음 요청까지 보류합니다. 사용 권한과 PLAN 정책은 유지합니다.
3. **입력 근거 표시**: `/rules explain 파일경로`에서 포함·범위 밖·예산 초과·잘못된 규칙을 확인하고, `/rules last`·`/usage`에서 마지막 요청의 규칙 수와 추정량을 확인합니다. 규칙 본문을 대화 이력에 자동 누적하지 않습니다.

사용 방법과 정확한 제한은 [변경 영향·규칙 가이드](frontend-impact-and-rules.md)를 참고하세요. npm `0.10.0`에는 포함하지 않았으며 최신 GitHub 소스에서 실행합니다.

### 측정 범위

파일 그래프·예산·캐시 무효화·규칙 선택·실제 요청 포함·편집 보류·PLAN 제한은 자동화 테스트로 확인합니다. 규칙 테스트의 공급자는 고정 응답을 반환하며 외부 모델을 사용한 품질 평가는 아닙니다. 캐시 적중은 파싱 비용의 재사용이지 API 토큰 절감률이 아닙니다. 새 규칙 때문에 편집이 보류되면 모델 호출이 늘 수 있습니다.

동일한 실제 작업에 대해 변경 성공, 동일 UI 검사 통과, 추가 오류, 입력·출력 토큰, 호출 수와 소요 시간을 함께 기록해야 제품 간 품질·비용을 비교할 수 있습니다.

## 이번 구현

`/map 검색어`와 모델용 `repository_map` 읽기 도구를 추가했습니다. 전체 원본 대신 최상위 함수·클래스·타입·변수와 상대경로 import 관계를 보여줍니다. Vue·Svelte는 script 영역을 분석하고 파일 기반 컴포넌트 이름도 표시합니다. Angular는 TypeScript 선언을 분석합니다.

검색어와 파일명·심볼명 일치도, 직접 참조 횟수로 정렬합니다. Aider의 그래프 순위 알고리즘을 재현한 구현은 아닙니다. 기본 예산은 추정 1,600 토큰이며 모델 도구에서는 256–4,000 범위로 선택합니다. 파일 본문을 읽은 것으로 간주하지 않으며 편집 전 원본 읽기 정책은 유지합니다.

파일별 해시로 메모리 캐시를 갱신하고 import 연결은 지도 생성 때 다시 계산합니다. 자동으로 매 요청에 삽입하지 않으며 필요한 때만 호출합니다. 최대 120개 파일·2 MiB를 분석합니다. 별칭·동적 import·템플릿·전체 호출 관계를 완전히 해석하지 않습니다. 심볼 목록도 상한이 있으며 TypeScript 선택 의존성이 필요합니다.

테스트는 프레임워크 소스 형태, 예산 준수, 캐시 무효화, 취소, PLAN 읽기 도구 등록을 확인합니다. 실제 작업 완료까지의 토큰 절감률이나 경쟁 제품 대비 품질 우위는 측정하지 않았습니다.

## 추가 비교: 작업 이어가기

- [Gemini CLI 명령](https://geminicli.com/docs/reference/commands/): 대화 저장·재개와 Markdown/JSON 내보내기 제공.
- [Cline 작업 관리](https://docs.cline.bot/core-workflows/task-management): 작업 단위 이력 관리와 새 작업 흐름 제공.

OSCODE에는 `/summary`와 `/handoff`, `/handoff copy`를 추가했습니다. 모델 생성 요약 대신 세션의 최근 요청·파일 체크포인트·도구 결과 존재 여부와 오류 플래그·사용량을 로컬에서 정리합니다. 이전 요구사항은 최대 네 건의 발췌만 포함하며, 긴 소스 첨부와 스킬 본문·도구 입력 및 출력은 내보내지 않습니다. 원래 세션을 재개하는 명령도 안내합니다.

자동 요약의 환각과 추가 모델 호출을 피하는 대신, 설계 결정이나 미완료 항목을 의미적으로 추출하지 못한다는 한계가 있습니다. 도구 성공 응답을 검증 통과로 바꾸지 않습니다. 원본 세션과 실제 소스를 확인할 수 있도록 안내합니다. 외부 서비스에 전송하지 않으며 복사는 명시적인 `/handoff copy`에서만 수행합니다.
