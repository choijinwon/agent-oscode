# 변경 영향과 파일별 규칙

최신 GitHub 소스에서 사용할 수 있습니다. npm `0.10.0`에는 이번 기능이 포함되지 않았습니다.

## 공통 컴포넌트를 바꾸기 전에

```text
/impact src/components/Button.vue
/impact src/styles/tokens.css
```

비대화형 실행도 API 키 없이 사용할 수 있습니다.

```sh
node bin/oscode.js --cwd /path/to/project --impact src/styles/tokens.css
```

결과는 변경 파일을 참조하는 파일, 화면·테스트 후보, 소스 줄 번호가 있는 연결 경로입니다. 예를 들어 `tokens.css ← shared.scss ← InvoicePage.vue ← InvoicePage.spec.ts`를 따라 확인할 범위를 좁힙니다. 테스트 후보를 먼저, 화면 이름·폴더에 해당하는 후보를 그다음에 표시합니다. 파일 본문은 모델에 전달하지 않습니다.

모델은 프론트엔드 모드의 읽기 전용 `frontend_impact` 도구를 BUILD와 PLAN에서 사용할 수 있습니다. 공유 컴포넌트·스타일을 수정하기 전에 이 도구를 사용하도록 안내합니다. 실제 실행 여부는 모델의 도구 선택에 달려 있습니다. 검사를 자동 실행하거나 테스트 통과로 간주하지 않습니다.

| 결과 | 의미 |
| --- | --- |
| `affectedFiles` | 출력 예산 안에 포함한 참조 파일 |
| `testCandidates`, `pageCandidates` | 파일명·폴더 기준 검증 후보. 실제 테스트·라우트 등록을 보증하지 않음 |
| `evidence` | 후보에서 변경 파일까지의 import·스타일·템플릿 연결과 줄 번호 |
| `partial` | 스캔 한도, 해석 오류, 미해결 경로 등 확인된 불완전성. false도 전체 애플리케이션 검증을 뜻하지 않음 |
| `omittedAffected` | 영향은 찾았지만 출력 예산 때문에 보여주지 못한 개수 |
| `cache` | 현재 해시가 일치해 파싱을 재사용한 수와 다시 파싱한 수 |

React/JS/TS의 import·re-export·문자열 dynamic import, Vue/Svelte의 script import·외부 script/style, 따옴표로 지정한 CSS/SCSS `@import`·`@use`·`@forward`, Angular `@Component`의 `templateUrl`·`styleUrl`·`styleUrls`를 분석합니다. 루트 `tsconfig.json` 또는 `jsconfig.json`의 `paths`·`baseUrl`도 적용합니다. 파일의 현재 해시와 설정을 다시 확인하므로 내용 수정·삭제·별칭 변경을 다음 분석에 반영합니다.

최대 300개 소스 파일·2 MiB·3,000개 연결입니다. 파일당 120,000자를 넘는 소스는 생략합니다. 출력은 기본 추정 2,400 토큰, 모델 도구의 `tokens`는 800–4,000입니다. 최대 80개 후보, 후보당 연결 8개를 보여주며 잘린 연결은 `omittedEdges`로 표시합니다. 화면 이름 추정, SFC script/style 블록과 스타일 참조 추출에는 한계가 있습니다. 템플릿의 실제 바인딩, 자동 import, 동적 라우트, 번들러 별칭, tsconfig extends·프로젝트 참조, 전체 언어 서버 분석은 지원하지 않습니다.

파싱 캐시는 현재 프로세스의 메모리에만 보관합니다. 파일 읽기를 건너뛰는 캐시나 AI 답변 캐시가 아니며, 적중 횟수를 API 토큰 절감률로 해석하면 안 됩니다. 실제 수정은 원본을 읽고 기존 파일 도구와 승인 정책을 따라 수행해야 합니다.

## 파일에 맞는 규칙만 포함하기

작업 프로젝트에 `.oscode/rules/ui.md`를 만들고 다음처럼 저장하세요. `paths`는 **한 줄의 JSON 문자열 배열**입니다. 일반 YAML 전체 문법을 지원하는 설정 파일은 아닙니다.

```md
---
paths: ["src/components/**/*.{tsx,vue,svelte}", "src/**/*.component.ts"]
---
기존 공통 컴포넌트와 디자인 토큰을 우선 사용합니다.
변경한 버튼·입력·대화상자는 키보드 조작을 확인합니다.
공통 스타일 변경 전 영향받는 화면과 테스트 후보를 확인합니다.
```

페이지 전용 규칙은 별도 파일로 나눕니다.

```md
---
paths: ["src/pages/accounting/**"]
---
금액의 통화와 소수점 자릿수를 명시합니다.
합계·반올림은 프로젝트에 이미 정한 계산 모듈을 사용합니다.
전표 저장 실패와 빈 결과 상태를 확인합니다.
```

복사할 원본은 `examples/project-rules/ui.md`, `examples/project-rules/accounting.md`입니다. 실제 디렉터리와 팀의 규칙에 맞춰 수정하세요. 예시 파일은 자동 적용되지 않습니다.

```text
/rules
/rules explain src/components/Button.vue
/context add src/components/Button.vue
이 버튼의 모바일 줄바꿈을 수정해줘
/rules last
/usage
```

`/rules`는 현재 선택한 파일 기준 목록, `/rules explain 파일경로`는 해당 파일에 대한 미리보기, `/rules last`는 마지막 모델 요청 당시 기록입니다. 포함·범위 밖·예산 초과·형식 오류와 일치한 파일, 입력 토큰 추정을 표시합니다. 미리보기는 선택 상태를 바꾸지 않습니다.

- `@파일`과 `/context add`로 첨부한 파일의 규칙은 첫 모델 요청에 포함합니다.
- 이번 턴의 `read_file` 또는 `frontend_context`로 확인한 대상 파일의 규칙은 다음 모델 요청에 추가합니다. 의존 파일이 출력에 언급됐다는 이유만으로 모든 관련 규칙을 불러오지는 않습니다.
- 파일 편집·생성 전에 새 규칙을 발견하면 해당 작업을 보류하고 다음 모델 요청에 규칙을 보여준 뒤 재시도하게 합니다. 한 응답에서 읽기와 편집을 함께 요청해도 같은 조건이 적용됩니다. 이 경우 추가 모델 호출이 필요할 수 있습니다.
- 각 모델 요청 전에 규칙 파일을 다시 읽습니다. 다음 턴은 선택 파일 기준으로 범위를 다시 시작하며, 이전 턴의 규칙 본문을 대화 이력에 누적하지 않습니다. 모델이 이전 응답에서 규칙을 인용했다면 그 인용문은 대화에 남을 수 있습니다.

규칙 파일은 `.oscode/rules/` 바로 아래 Markdown만 지원합니다. 하위 디렉터리·심볼릭 링크·외부 파일 import·스크립트 실행은 지원하지 않습니다. 사전순 첫 40개, 파일당 8 KiB, 규칙당 1–8개 패턴과 확장 후 합계 32개, 한 턴 최대 100개 파일로 제한합니다. `*`, `**`, `?`, `{ts,tsx}`를 지원하며 `..`·절대 경로는 허용하지 않습니다. 대괄호 문자 클래스 등 전체 glob 문법은 지원하지 않습니다.

본문은 합계 추정 2,000 토큰 안에서 규칙 단위로 포함합니다. 초과한 규칙은 조용히 자르지 않고 목록과 알림에 생략 이유를 표시합니다. 필요한 규칙이 생략되면 파일을 나누거나 내용을 줄이세요. 공통 지침은 기존 `AGENTS.md`, 사용자가 직접 선택할 작업 절차는 `/skills`에 두세요.

규칙은 모델을 위한 지침이며 강제 정책·추가 실행 권한이 아닙니다. PLAN·사용자 요청·승인·경로 제한을 변경하지 않습니다. 셸이나 외부 MCP 도구의 개별 파일 접근을 추적해 규칙을 강제하는 기능은 아닙니다.

## 확인한 범위

자동화 검증은 네 프레임워크와 스타일·템플릿의 참조 연결, 캐시 무효화, 출력 한도, 누락 표시, 규칙 범위·갱신·생략, 실제 에이전트 요청에 포함되는 지침, 편집 보류·재시도와 PLAN 제한을 확인합니다. 모델 응답은 테스트용 공급자를 사용합니다. 실제 외부 모델의 수정 성공률이나 경쟁 제품 대비 토큰 절감률은 측정하지 않았습니다.
