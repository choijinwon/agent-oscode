# 프론트엔드 전문 에이전트

`oscode --agent frontend`는 기존 PLAN/BUILD와 독립적인 전문 모드입니다. React/Next.js, Vue/Nuxt, Svelte, Astro, Vite와 주요 스타일·테스트 도구의 **의존성 선언**을 파악하고 기존 컴포넌트와 스타일을 활용하도록 모델을 안내합니다.

```sh
# 로컬 진단: 모델/API 키 없이, 스크립트 실행 없이
oscode --cwd ./my-app --inspect-frontend

# 설정된 모델로 UI 개선 계획 작성
oscode --cwd ./my-app --agent frontend --plan --prompt '로그인 폼의 모바일 레이아웃과 키보드 접근성을 개선해줘'

# 계획 확인 후 명시적으로 실행
oscode --cwd ./my-app --resume latest --apply-plan
```

대화 중 `/agent frontend`, `/agent general`로 전환합니다. `/frontend`는 진단만 표시하며, `/frontend apps/web`처럼 모노레포 앱 경로를 지정할 수 있습니다. API 없는 진단은 `--cwd apps/web --inspect-frontend`를 사용하세요. 전문 모드는 세션과 계획에 저장되며 계획 실행 시 작성 당시 전문 모드를 복원합니다.

프로젝트 `oscode.json`에 `"agent": "frontend"`를 추가하거나 `OSCODE_AGENT=frontend`를 설정할 수 있습니다. CLI > 환경 변수 > 프로젝트 설정 > 재개 세션 > general 순서입니다.

## 제공하는 작업 흐름

- `frontend_inspect`: 읽기 전용 스택·패키지 매니저·스크립트 이름·컴포넌트/라우트/스타일/테스트 경로 요약. 스크립트 본문이나 전체 소스를 자동 수집하지 않습니다.
- 기존 디자인 시스템 재사용, 서버/클라이언트 경계 유지, 로딩·빈 화면·오류 상태를 포함하도록 전문 지침 적용.
- 의미 있는 HTML, 접근 가능한 이름, 키보드 포커스, 반응형 레이아웃, 모션 감소와 실제 존재하는 검증 스크립트를 고려.
- PLAN에서는 조사와 검증 계획만 작성. BUILD에서도 기존 파일 변경/셸 승인과 토큰 예산을 그대로 적용.

## 토큰과 검증 범위

진단 자체는 모델을 호출하지 않습니다. 모델이 요청한 진단 결과와 전문 지침은 기존 입력 토큰 예산에 포함됩니다. 파일 목록은 최대 3,000개, 분류별 예시는 10개이며 도구 출력 한도도 적용됩니다. 일반 모드에는 전문 지침/도구 정의를 추가하지 않습니다. 저장소 전체 소스를 자동으로 모델에 넣지 않습니다.

v0.5부터 [브라우저 UI 진단](ui-check.md)으로 스크린샷·가로 넘침·브라우저 오류를 수집할 수 있습니다. 기준 스크린샷 비교는 아직 제공하지 않습니다. 화면·접근성·성능 통과를 보장하지 않으며, 실제 실행한 검증과 수동 확인 항목을 구분하도록 안내합니다. 감지는 설치/실행 성공 여부가 아닌 package.json 선언 기준입니다. 패키지 매니저를 판별하지 못하면 추측 명령 대신 unknown을 표시합니다. 모노레포는 앱 디렉터리별로 조사하세요.
