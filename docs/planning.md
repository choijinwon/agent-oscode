# oscode 플랜 모드

플랜 모드는 코드를 바꾸기 전에 프로젝트를 조사하고 구현 계획을 검토하는 흐름이다. 터미널 프롬프트의 `[PLAN]`과 `[BUILD]`로 현재 모드를 확인할 수 있다.

## 대화 중 사용

```text
/plan 로그인 기능을 리팩터링할 계획을 세워줘
/plan show
/apply
```

`/plan 요청내용`은 파일 목록·검색·읽기를 통해 조사한 뒤 계획을 작성한다. 모델에게 목표, 조사한 파일, 순서가 있는 구현 단계, 나중에 실행할 검증 명령, 가정·위험·미해결 질문을 포함하도록 요청한다. Markdown 형식의 모델 초안이며 내용의 완전성을 자동 보증하지 않는다.

계획을 수정하고 싶다면 플랜 모드에서 변경 요청을 입력한다. 매번 새 버전으로 저장하며 `/plan list`로 이력을 확인한다. `/plan show`는 최신 계획을 표시한다. 최신 계획이 실패했거나 미완성이라면 이전 버전을 자동으로 실행하지 않는다.

`/apply`는 최신 계획을 보여주고 실행 여부를 묻는다. `y` 또는 `yes`로 확인하면 구현 모드로 전환해 실행한다. `--yes`를 지정했더라도 대화형 계획 확인은 건너뛰지 않는다. 확인을 취소하면 모델 호출이나 구현을 시작하지 않는다.

계획을 실행하지 않고 모드만 바꾸려면 `/plan off`를 사용한다. `/plan` 또는 `/plan on`은 플랜 모드로 돌아간다. 모드 전환과 계획 조회에는 모델을 호출하지 않는다.

## 비대화형 사용

```sh
# 조사와 계획 작성
node bin/oscode.js --model YOUR_MODEL_ID --plan --prompt '로그인 기능 리팩터링 계획'

# 저장된 최신 세션의 계획 조회: API 키 불필요
node bin/oscode.js --resume latest --show-plan

# 검토한 계획 실행
node bin/oscode.js --model YOUR_MODEL_ID --resume latest --apply-plan
```

여러 세션이 있다면 `latest` 대신 계획을 작성한 세션 ID를 지정한다. `--apply-plan`은 계획 실행의 명시적 승인이다. `--prompt`, `--plan`, `--demo`와 함께 사용할 수 없다.

계획 승인은 도구 권한과 별개다. 비대화형 실행에서 파일 변경을 허용하려면 `--yes`, 셸 명령까지 자동 허용하려면 `--allow-shell`을 사용자가 별도로 지정한다. 지정하지 않으면 승인 입력을 받을 수 없는 변경을 거절한다. 프로젝트의 `deny` 규칙은 그대로 적용된다.

## 변경 차단과 저장

- 모델에게는 파일 목록·검색·읽기 도구만 제공한다.
- 모델이 편집·생성·셸 도구를 반환해도 에이전트 실행 단계에서 차단한다.
- 도구 계층의 읽기 전용 검사도 유지한다. `/test`와 `/undo`는 플랜 모드에서 실행되지 않는다.
- 세션과 계획을 보관하는 내부 `.oscode/` 기록은 저장한다. 따라서 OS 수준의 모든 쓰기를 막는 샌드박스는 아니다.
- 프로젝트 설정의 `plan: true`와 데모 모드는 잠금 상태다. 실행 전환으로 해제할 수 없다.

계획 작성 때도 기존 입력·출력·누적 토큰 예산과 반복 감지를 적용한다. 계획 저장을 위해 별도 요약 모델을 부르지 않는다. 실행 요청에는 승인한 계획을 넣고 그 계획을 만들었던 조사 턴은 중복 전송하지 않는다.

계획은 대화와 별도로 세션에 저장되므로 `/compact` 이후에도 남는다. 플랜 모드에서 저장한 세션을 재개하면 같은 모드가 유지된다. 구현을 시작할 때는 파일이 바뀌었을 수 있으므로 다시 확인하도록 모델에 지시하고, 실제 편집 전 읽기 검사도 수행한다.

## 상태와 재개

- `planning`: 작성 중.
- `draft`: 저장된 계획 초안. 사용자 검토 후 실행 가능.
- `failed`: 계획 작성 실패·취소. 실행할 수 없음.
- `running`: 승인된 계획 실행 중.
- `stopped` / `interrupted`: 실행 중단. 현재 파일을 확인하고 `/apply`로 명시적으로 다시 시작 가능.
- `completed`: 모델 실행 턴이 정상 종료됨. 모든 검증 성공을 별도로 보증하는 상태는 아니므로 실제 응답과 도구 결과를 확인해야 함.

이미 종료한 계획은 실수로 재실행하지 않도록 다시 적용할 수 없다. 새 작업이나 추가 수정이 필요하면 새 요청으로 계속하거나 새 계획을 작성한다. 계획이 참조하는 외부 변경을 자동 병합하거나 모든 단계의 완료 여부를 기계적으로 판정하는 기능은 포함하지 않는다.
