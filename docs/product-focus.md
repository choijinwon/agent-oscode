# OSCODE 기능 집중 검토

핵심 사용자: 프론트엔드 화면의 변경을 직접 구현하고 검증하는 개발자.
핵심 흐름: 녹화 → 상태 재현 → 실패 확인 → 승인된 수정 → 동일 조건 재검증 → 근거 확인.

## 유지하고 강화한 기능

- `/states record`, `/states run`, `/states fix`: 하나의 JSON 시나리오를 재사용합니다.
- UI 수정 보고서: 최초 시나리오를 보존하고 중단·환경 불일치·검증 미완료를 구분합니다.
- 실제 런타임 오류와 모의 HTTP 오류를 구분합니다. 예상된 모의 오류는 재현 근거지만 실제 HTTP 실패·처리되지 않은 JS 오류는 해결 판정을 막습니다.
- 첫 실패 때문에 후속 모의 응답이 사용되지 않은 경우에는 AI 수정이 가능하도록 변경했습니다. 재검증에서는 계획된 모의 응답이 모두 사용되어야 합니다.
- 모델 연결을 먼저 점검해 연결되지 않은 상태에서 AI 수정용 브라우저 검사를 먼저 실행하지 않습니다. 키 없이 검사하려면 `/states run`을 사용합니다.

## 주 메뉴에서 제외한 기능

빈 `/` 메뉴와 빈 명령 검색에는 녹화·실행·수정·미리보기·모델 설정·작업 폴더·프로젝트 검증·도움말 8개만 표시합니다. OCR, 글자 스타일, 스킬, 인계, 토큰 세부 설정 등은 명령 일부나 한국어 설명으로 검색할 수 있습니다. 기존 명령·저장 데이터는 삭제하지 않습니다.

이 기능들이 무용하다는 사용자 근거는 없으므로 구현 자체를 삭제하지 않았습니다. 지금은 새로운 모델·테마·첨부 유형을 늘리기보다 핵심 검증 흐름의 성공률과 사용성을 우선합니다.

## 확인한 범위와 남은 검증

자동화 테스트는 코드 회귀와 일부 실제 Chromium 동작을 확인합니다. 외부 AI 모델을 사용한 다양한 실제 프로젝트의 수정 성공률, 시간·비용 절감 효과와 수상 가능성을 증명하지는 않습니다. 평가할 때는 원본 실패 재현 여부, 수정 후 동일 검사 통과 여부, 추가 오류, 사용자 승인 횟수와 실제 토큰 사용량을 함께 기록해야 합니다.
